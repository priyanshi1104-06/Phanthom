Code, unmasked.

Phantom checks your code while you write it. When it says a function is broken, it shows you the exact input that breaks it, because it has already run it.

{{cta_label}} How it works

It doesn't guess.

Each time you stop typing, Phantom takes the functions you just changed and calls them with the inputs that tend to break code: an empty list, zero, a negative number, an empty string. Every call runs in a throwaway container with no network and no way to reach your files.

When a call fails, Phantom runs it again on its own, in a new container. Only if it fails the same way does it reach your editor, with the input, the error and a button to replay it once you've fixed the code. A warning you can't reproduce isn't worth your time, so you never see one.

It catches the wrong answers too.

Some bugs never crash. is_leap_year(1900) returns True and carries on as if nothing happened. Phantom reads the examples you already write in comments and docstrings and holds the code to them. With its AI turned on, it also reads what each function is meant to do and checks that, quoting the line in your code it relied on, so you can judge for yourself.

Change a function and it re-checks everything that calls it, so a fix in one place that quietly breaks another shows up where the damage is.

Three layers, from quick to thorough.

Specter
Runs on every pause in typing and takes about a second per function. Crashes, hangs, and values a function's own types say it can't return.
Analyst
Runs when you open or save a file, or make a risky edit. Wrong answers, and callers an edit has broken.
Oracle next
For the riskiest changes: an agent in the sandbox that writes tests, digs deeper and proves a fix works before you apply it. It's the next thing we're building.

Phantom works in Python, JavaScript, TypeScript, Go, Java, C, C++, Rust, Ruby and PHP, using each language's real compiler or runtime.

What happens to your code.

It stays on your machine. Phantom's engine and its sandboxes run on your own computer. The AI is optional: without it, Phantom still finds and proves bugs; with it on, the function being checked is sent to the model so it can suggest inputs and read the intent.

And Phantom will never tell you your code is bug-free. When it finds nothing, it says exactly that: none of the inputs it tried made your code fail.

Try it.

Phantom is free while it's in early access. It runs in VS Code and needs Docker and Python 3 on your machine.
